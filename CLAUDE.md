# Project Instructions

Distributed railway reservation platform. Turborepo + pnpm workspaces.
Domain-Driven Design, Clean Architecture, microservices with both REST
(per service) and gRPC (service-to-service).

## Stack

- Node.js (TypeScript, `nodenext`, strict mode, `verbatimModuleSyntax`)
- Express 5
- Prisma (PostgreSQL)
- Redis (ioredis) — caching, idempotency, distributed locks
- Kafka (kafkajs) — outbox pattern for publishing, consumers with idempotency
- gRPC (nice-grpc) — service-to-service RPC
- OpenTelemetry, Pino, Zod

## Apps

- `admin-service` — domain admin (trains, stations, routes, schedules, coaches, seats)
- `user-service` — registration, auth, profile
- `booking-service` — seat allocation and reservation
- `payment-service` — payment processing and verification
- `search-service` — train / station search with Redis caching
- `notification-service` — event-driven notifications
- `inventory-service` — schedule / seat projections, hold lifecycle, **gRPC server (Inventory)**
- `api-gateway` — REST entry point, routing, auth middleware, rate limiting

## Common commands

- `pnpm build` / `pnpm dev` / `pnpm lint` / `pnpm check-types` / `pnpm format`
- `pnpm turbo run build:spec` — regenerate per-service OpenAPI specs and the merged gateway spec
- `pnpm turbo run generate:api` — regenerate the frontend SDK from the merged gateway
- `pnpm --filter <service> prisma generate` / `prisma migrate dev`
- `pnpm --filter @irctc/contracts build` — regenerate Kafka + gRPC types after a proto or Zod schema change

## Key invariants

- Controllers never call Prisma, Redis, or Kafka directly.
- Services never call Prisma directly — go through repositories.
- All Kafka payloads are versioned Zod schemas in `@irctc/contracts`.
- All gRPC service definitions and clients are generated by `buf` into `@irctc/contracts`.
- All user-facing error messages live in the service's `utils/errors` registry.
- Never log PII (`email`, `phone`, `firstName`, `lastName`, full bodies).
- Publish events via the **transactional outbox**, not the producer, inside services.
- gRPC handlers throw `ApiError`; `@irctc/grpc` translates to `ServerError` at the boundary.

## Documentation philosophy

Generated infrastructure (OpenAPI, orval output, buf-generated gRPC types, regenerated specs) is documented at an architectural level on the producer that emits it, not in the output. Hand-written source files get rich file-level and per-export JSDoc — see the `jsdoc` skill for the full standard. The one hard rule: **never write a literal `*/` inside a JSDoc block** — it closes the comment early. Rephrase as prose, escape the slash (`app&#x2F;s`), or use a placeholder (`<id>`).

## Commit messages

Follow `@commitlint/config-conventional` (see `package.json`). The user generates commit messages for substantial work; do not auto-commit unless explicitly asked.
