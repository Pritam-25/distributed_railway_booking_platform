# Invariants

Non-negotiable rules that apply across every service. If you find yourself about to break one, stop and look for the layered path instead.

## Layer boundaries

- **Controllers** never call Prisma, Redis, or Kafka directly. They take validated input and call services.
- **Services** never call Prisma directly — always through repositories. Services own transactions and outbox writes.
- **Repositories** are the only layer that touches Prisma, Redis (when wrapped), or external state stores. They accept an optional `tx?` for transaction propagation.
- **Routes** wire validation middleware and delegate to controllers — no business logic.

## Contracts and code generation

- All Kafka payloads are **versioned Zod schemas** in `@irctc/contracts` (e.g. `StationCreatedEventV1`).
- All gRPC service definitions and clients are **generated by `buf`** into `@irctc/contracts`. Never hand-write service definitions.
- All OpenAPI envelopes and shared error responses live in `@irctc/openapi` — never duplicate them in a service.
- Generated infrastructure (orval output, buf-generated gRPC, regenerated specs) is **never edited by hand** — change the producer, regenerate.

## Errors

- All user-facing error messages live in the service's `src/utils/errors/` registry (`ERROR_CODES` + `ERROR_MESSAGES`).
- Throw `ApiError`, never raw `Error`. Never `catch` an `ApiError` to rethrow as another — let `errorHandler` see the original.
- `errorHandler` is mounted last in `app.ts`. Never handle errors inline in controllers.

## Logging and PII

- Never log PII: `email`, `firstName`, `lastName`, `fullName`, `phone`, `address`, `dateOfBirth`, full request/response bodies, full Kafka payloads.
- Use stable identifiers instead: `eventId`, `userId` (when authenticated), `sessionId` (when not), `aggregateId`, `requestId`.
- `REDACT_PATHS` in `packages/logger/src/constants.ts` is the single source of truth for credential redaction. Add new fields there, not in the service.

## Cross-service communication

- **Events**: publish via the **transactional outbox**, not directly from the producer. The outbox worker drains the table to Kafka after the transaction commits.
- **gRPC**: handlers throw `ApiError`; `@irctc/grpc` translates to `ServerError` at the boundary. Callers catch `ClientError` and translate back to `ApiError`.
- Never hold a Prisma transaction while doing I/O outside the DB — publish from the outbox worker after commit.

## When in doubt

The wrong layer is the one that breaks the rule. Find the path that respects the layering; if it feels like more code, it is the correct code.
